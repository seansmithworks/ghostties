02 · The story

What we're actually onboarding people into

Your agents, in a row. See what's running, what needs you, and click straight back in.

Built from mission.md's promise. The audience is moderately savvy: they installed a terminal on purpose and probably already run Claude Code or Codex. The terminal itself is upstream Ghostty, unchanged. That's a trust signal to state once, not a feature to teach.

Promote
  • Many agents, one window
  • "Needs you" status at a glance
  • It's Ghostty underneath: fast, native, your config
Set up (do it for them)
  • Add projects: detect from ~/.claude/projects and repos you already have
  • Connect Claude Code + Codex hooks
  • Notification permission, asked when it's needed
Teach (first session)
  • Project → sessions
  • ⌘T composer: project › branch › template
  • Status glyphs and "needs you"
  • ⌘⇧[ ⌘⇧] to move between sessions
Later, when relevant
  • Templates and presets
  • Browser ⌘B
  • Menu bar status, task-first view
  • MCP sources, CLI (see the CLI page)

03 · Research

What good dev-tool onboarding does

Each pattern below is backed by a source. Ghostty and Warp pages couldn't be fetched directly, so those claims come from their own pages' search snippets. Mobbin covers mobile, not Mac apps, so it was no help here.

Win on the user's own code

Claude Code's quickstart has you ask "what does this project do?" in your own repo. Codex app: sign in, pick a folder, send a message.

code.claude.com/docs/en/quickstart · developers.openai.com/codex/app

Import, don't ask

Cursor, Zed and Dia import existing settings, and each import can be re-run later. For us that means detecting projects Claude Code already knows about.

zed.dev/docs/migrate/vs-code · diabrowser.com

Tutorials as real content

Things ships "Meet Things" as an ordinary project you can recreate from Help. Linear's onboarding arrives as real issues.

culturedcode.com

One meaningful choice, early

Raycast asks for your hotkey and nothing else. Ask only what changes daily muscle memory.

manual.raycast.com/quickstart

Detect, don't configure

Claude Code says Ghostty, Kitty and iTerm2 need no terminal setup. Don't add setup steps for things that already work.

code.claude.com/docs/en/terminal-config

Zero-config is the upstream ethos

Ghostty ships no onboarding and writes a comment-only default config. Ours should feel as light: skippable, re-openable, never repeated.

ghostty.org release notes 1.0.1

AvoidEvidence
Forced accounts at first launchWarp removed its login requirement after backlash. warp.dev/blog
Promoting AI features in a popup after an updateiTerm2 3.5's ChatGPT popup drew GitHub issues asking for the feature's removal. HN thread

04 · Concepts

Mild, wild, wilder

Each prototype is a click-through of the real window. All three share the setup work (detection, one-click hooks), so whichever wins, that work isn't wasted.

MILD

A sheet that does the setup

Replace OnboardingSheet with a three-step Liquid Glass sheet. Every step does something real: projects are pre-detected and checked, the hook install shows the exact JSON it adds, and the last step shows the three shortcuts that matter.

Effort~1 week. Swift, SwiftUI sheet, plus a hook installer that merges JSON safely.
RiskLow. It's still a modal. Has to keep the demo-capture launch flag that suppresses it.
GhostsThe row of ghosts on step 1 becomes the projects' assigned ghosts on step 2.
WILD

The window teaches

No modal. The empty terminal card's physics ghosts assemble the wordmark. A Meet Ghostties project appears in the sidebar (re-creatable from Help, like Things). Its sessions are the checklist, and the first one is a real agent session that reaches "needs you", so you learn the core loop by living it once.

Effort2–3 weeks. Reuses WordmarkPhysics (flag already exists), SidebarCalloutCard, ComposerWitness frames.
RiskMedium. A tutorial project must never feel like clutter: one click archives it.
Aha momentThe first terracotta "needs you" glyph, plus the notification, within about 60 seconds.
WILDER

Ghost in the shell

The onboarding is a terminal program. On first launch the card runs ghostties hello: a half-block ghost greets you, arrow-key pickers handle choices, and an agent does the setup. It finds your repos, proposes projects, and writes the hook config after you approve the diff. At the end the sidebar fills in. A glass ghost rendered in Metal is the one hero moment.

Effort4–6 weeks. TUI script, agent prompt and preset, Metal shader, a reduced-motion path.
RiskHigh. It depends on an agent CLI being installed and signed in. Needs a no-agent fallback that becomes Mild.
WhyIt's the most "us": a terminal that onboards you in the terminal, with agents doing the work.
05 · Character

Glass ghosts

I couldn't find the glass robot ghost designs anywhere in the repo or its history. The renders below are a stand-in built from the real 12×12 grids with a glass treatment, to test whether glass reads at small sizes. Send the source files (Figma?) and I'll match them.

Where glass belongs. Glass suits hero moments: the Wilder greeting, the Mild step-1 header, the website. Keep sidebar glyphs flat. They're 20pt and have to read at a glance.

Native path. SwiftUI Canvas + .layerEffect with a Metal shader for refraction and specular highlights. Falls back to the flat grid under Reduce Transparency or Reduce Motion.

Personality, in budget. Brand.md says the ghosts carry the personality so the copy doesn't have to. One ghost per project and one hero moment. No mascot chatter.
