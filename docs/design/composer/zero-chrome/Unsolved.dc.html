Unsolved — what the first canvas did not answer
Ten open details, worst first
You said the detail has to be crisp. These are the places it currently is not. Numbers 1 and 2 can each sink the direction on their own; the rest are work, not risk.
01
Where it sits Blocking
Centre-float vs. docked band. Everything else on this list changes depending on the answer — pick the docked band and items 03, 04 and 05 stop existing. Drawn on the previous board.
Settled by Your call. Nothing to build first.
02
Reduce Motion deletes the interface Blocking
The whole direction rests on motion carrying the mode signal, because nothing else is left to carry it. Turn on Reduce Motion and there is no blur ramp, no lift, no stagger — and no card either. Text simply exists, with nothing to say a mode opened. Every other direction in the set degrades gracefully here; this one has no floor.
Settled by Designing the static fallback. If it needs a surface, the direction has a surface.
03
Live output scrolling underneath High
A build is running; lines move behind stationary text. The card hid this completely. Nobody has seen what it looks like — and moving content under fixed type is the classic way an overlay reads as broken rather than deliberate.
Settled by A 10-second capture with npm run build going. Cheap, and it may kill the direction outright.
04
Other people's terminal themes High
Every value on the first canvas assumes canvas #2D2D2D / #FAF7F3. Ghostty users theme their terminals heavily — solarized, high-contrast, bright custom backgrounds. Contrast is computed against a background you do not control and cannot predict.
Settled by Deriving the wash and ghost opacity from the live theme, not from DESIGN.md constants.
05
Blur depth is a guess High
6px was picked to look right in a static mock. Raycast v2 ships 48px. Eight times is not a tuning difference, it is a different idea of what blur is for.
Settled by Measuring against real scrollback, not a fixture.
06
Hover has no shape Medium
Rows have no background, so there is nothing to highlight on mouse-over. Since PR #155 removed the picker controls, the list is the only mouse surface left in the composer — and this direction gives it no hover state at all.
Settled by Deciding whether hover tints the glyphs, or the composer goes keyboard-only.
07
Nothing bounds the width Medium
The card capped at 360pt and truncated the ghost path to one line. Remove it and a long project path has no edge to hit. Wrap, truncate, or run the full width of the terminal — all three look wrong for different reasons.
Settled by Keeping the 360pt measure as an invisible constraint.
08
Nothing bounds the row count Medium
The card gave the list a visual stop. Floating text does not have one — twelve results become a column of free-standing type down the middle of a terminal.
Settled by A hard cap, probably 5, with no "more" affordance to draw.
09
VoiceOver loses its container Medium
The card was the thing that got announced as a group. The lanes already carry accessibilityLabels, but the outer grouping element goes away with the surface.
Settled by An explicit accessibility container that renders nothing.
10
The armed-segment tint may not be buildable Medium
Already flagged on the Flow page — reference_composer-field-cannot-tint-subranges says the field cannot colour sub-ranges at the macOS 13 floor. It needs the ghost-subview trick, or it degrades to no tint.
Settled by A spike, or accepting the degrade.
The cheapest next move is 03. Ten seconds of capture with a build running answers the one question that no amount of static mockery can, and it is the failure mode most likely to make this direction feel wrong in a way that is hard to argue with afterwards. Everything else on this list is worth doing only if that looks acceptable.
