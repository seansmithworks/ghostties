Background smoke harness

Plan only. Seams cited against feat/composer-one @ f5560a264 (landing on main for beta.26).

Recommendation: one script, scripts/smoke.sh, runs two layers against a separately named Smoke build. No keystrokes, no clicks, no XCUITest, no Accessibility permission. The app opens itself in the requested state, reports its own layout to a JSON file, and the script takes one window capture per state.
  • Layer 1, offscreen view tests: pixel and geometry checks inside the existing GhosttyTests, styled like SessionRowGlyphSlotTests. These run with no app window and no prompt, so they are safe during a call. Exact centring, glyph slots and tray counts belong here.
  • Layer 2, launched fixture app: one launch per state from env vars. It checks things only a real window shows: real blur, overlay centring inside an actual window, and whether the popover is still on screen.
  • Isolation is enforced, not hoped for. The Smoke build uses its own bundle id, com.seansmithdesign.ghostties.smoke, a temp state dir, a temp home folder and the in-memory fixture store. The app quits on launch if smoke mode runs under any other bundle id.
  • Assertions: the app reports its layout as JSON, and the script asserts on geometry and state from that file. PNGs are evidence for review, not golden baselines. Only JSON baselines get committed, because they contain invented fixture names only.
  • Appearance is pinned by a committed Ghostty config per run (the sidebar follows the terminal theme, not the system setting). Every run does both light and dark.
  • Focus: the app runs as a background accessory, with no Dock icon and no activation. It still shows a window, because a hidden window never draws (details below).
  • First slice: about 9 files and about 900 lines of code. It covers 3 of tonight's 4 smoke items fully and 1 partly. Click feel stays with you.
The one fork, "Layer 2 windows during a call": each state flashes a non-focused window on screen for about 8 s, and a screen share would show it. Default: the window goes on the secondary display if one is attached, otherwise the bottom-right corner. --quiet runs Layer 1 only. The alternative is that Layer 2 refuses to run until you pass --allow-windows. Choose that if you screen-share a lot.

3 · Isolation and quiet launch

  • Bundle id: build Debug with GHOSTTIES_DEV_BUNDLE_SUFFIX=.smoke, an existing build setting (project.pbxproj:1113/:1145), into macos/build-smoke. UserDefaults, the state folder name and LaunchServices identity are then all separate from Dev (.dev), Release and upstream com.mitchellh.ghostty. open can no longer focus Sean's Dev instance by mistake.
  • Fail closed: in applicationWillFinishLaunching (AppDelegate.swift:221), smoke mode with a bundle id that isn't .smoke, or without fixture mode, calls exit(78). This closes the "unknown bundle id falls through" class rather than checking for one case of it.
  • Data: the fixture store is in-memory and never persists, so workspace.json is never touched. The script also sets GHOSTTIES_STATE_DIR (WorkspacePersistence.swift:51) to a temp dir. It sets CFFIXED_USER_HOME to a temp home, because ~/.ghostties/hooks, ~/.codex/hooks.json (written at SessionCoordinator.swift:230) and ~/.claude/sessions are not scoped by bundle id.
  • Env hygiene: launch with env -u GHOSTTIES_SESSION_ID -u GHOSTTIES_LAUNCHER, or the app takes the session-join path and comes up as a bare terminal.
  • No focus steal: launch with open -g -n --env …. In smoke mode, call setActivationPolicy(.accessory) and skip the forced activate at AppDelegate.swift:474–478. A direct binary launch counts as a CLI launch and runs that forced activate, so that branch has to be gated.
  • Why a window must show: a covered instance never drew, and window captures came back blank (memory: the Dev capture occlusion trap). Off-screen and other-Space windows are probably occluded the same way (inferred). The Phase 0 spike checks this. If an off-screen window does draw, the fork above goes away.

4 · Assertions and baselines

  • The probe is in-process, not external AX. The app walks its own accessibility tree (accessibilityChildren, frames, identifiers). That needs no Accessibility grant for your terminal, so there is no grant that would also allow synthetic input. It records sidebar mode, tab, composer card frame, popover presence and identified element frames.
  • The script asserts per state with jq rules in scripts/smoke/states.tsv, for example abs(card.midX - content.midX) <= 1.
  • No golden PNGs. Your design changes weekly and font rendering moves between macOS versions, so image diffs would turn into noise to re-approve. Pixel truth lives in Layer 1 probes that measure one property each.
  • Committed baselines are macos/Smoke/baselines/<state>.json: structure only, with invented fixture names, so they are safe in a public repo. Screenshots go to macos/build/smoke-reports/<timestamp>/, which is gitignored.
  • Appearance: GHOSTTY_CONFIG_PATH (AppDelegate.swift:121) points at macos/Smoke/smoke-light.ghostty or smoke-dark.ghostty, which fix theme and font. GHOSTTIES_SMOKE_APPEARANCE sets NSApp.appearance for the AppKit chrome. Layer 1 already pins appearance per window.

5 · The runner

scripts/smoke.sh [--quiet] [--no-build] <state…|all>

  • Build: if the build is stale, run xcodebuild Debug with .smoke, arm64 only, into macos/build-smoke. In a worktree, first symlink the three gitignored inputs (GhosttyKit.xcframework, zig-out, vendor/cef) from the main checkout.
  • Preflight: the built Info.plist id must be .smoke, the display must be awake, and no other .smoke process can be running. Any failure aborts the run.
  • Layer 1: xcodebuild test -only-testing:GhosttyTests/<smoke suites> with the same suffix. The script stores the xcresulttool summary counts, not log lines.
  • Layer 2, per state and per appearance: launch; wait for ready (20 s timeout); find the window id by PID with scripts/smoke/winid.swift; run screencapture -x -o -l; run the assertions; send kill -TERM to that PID only. The PID is resolved from the .smoke bundle id, so it can only be the script's own instance.
  • Output: a summary.json and an index.html contact sheet per run. The script exits non-zero on any failure.
  • Brief line for orchestrators: "Run scripts/smoke.sh all. PASS only if summary.json is all-pass. Send the contact sheet via SendUserFile. Never send input to any Ghostties process. Write anything that needs a click into the human checklist."

6 · Phasing

  1. Phase 0, 30-minute spike, no commit: verify open --env reaches the app; CFFIXED_USER_HOME redirects ~ and defaults; the in-process accessibility walk returns SwiftUI frames; whether an off-screen or covered window still draws. Each check has a fallback: a launcher script; fixture-only with no home redirect; .anchorPreference frame reporting; a visible corner window.
  2. Phase 1, covers tonight's list: the Smoke build plus fail-closed guard; the TAB, COMPOSER and SETTINGS hooks; SmokeProbe; smoke.sh; 8 states (rail closed projects composer-new composer-row templates templates-edit templates-delete), each in light and dark; and the 2 new Layer 1 suites.
  3. Phase 2, later: wire the existing marketing and visual-pass captures onto the same hooks and retire their XCUITest launch path, which is what brings the UI-automation prompt.
What this can't catch
  • Interaction feel: hover delay, motion curves (Flow 05), drag, scroll inertia, click hit areas.
  • Click-to-seam wiring: a + that is drawn correctly but wired to the wrong action still passes Layer 2.
  • Key-window styling: runs are never focused, so the caret, focus rings and active-window materials go unseen.
  • Live data: real Claude session states, real git repos, worktree enumeration and multi-window ownership.
  • Reduce Motion and Increase Contrast are untouched unless they get added as states later.

Risks seen in the code, not fixed here
  • Existing "offscreen" Layer 1 tests flash a window. They call orderFrontRegardless() on a borderless window (SessionRowGlyphSlotTests.swift:73), so they briefly put pixels on screen.
  • Unit tests share Sean's Dev defaults. They run in the .dev test host today, so UserDefaults.standard writes land in Sean's Dev defaults domain. Running them under .smoke isolates them as a side effect.
