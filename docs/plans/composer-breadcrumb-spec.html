Composer breadcrumb + optional branch

Ghostties · 2026-08-22 · spec, awaiting your comments · follows slice 1 (a13de1f16)

The grammar

Every segment after the first is optional, and omitting one means "default."

ghostties                        → scope to repo, nothing launched
ghostties cco                    → repo + template, default branch
ghostties > main > cco -n "test" → repo + branch + ad-hoc command
  • Omitted branch means "wherever the project points right now" — not a remembered last-used branch. No hidden state, nothing to go stale, and it is exactly today's behavior.
  • The parser does not change. Slice 1 already tokenizes on whitespace at ≥2 tokens. > is rendering, not syntax — which retires the "positional vs sigils" question from the original grammar spec.
  • Single token stays byte-identical, protecting the fast path exactly as slice 1 does.

Slice A fixes a bug we are already carrying

The project label is a trailing control competing with the search field for width, with no layoutPriority and no cap on either. A long project name both truncates and halves the field. Moving the project into the field as a chip removes the second control entirely — the layout problem disappears rather than getting tuned.

It also makes the parse visible. Today the only signal that token 1 resolved is a label changing in the corner.

Build the chip picker as an inline expansion inside the card, not a nested popover. The project dropdown is already a .popover nested inside the composer's own .popover — on the known-fragile list, never verified, and a child taking key can dismiss the parent. From a sidebar row, two chips means two chances to lose the composer. An inline expansion fixes the existing fragility instead of doubling it. Cmd+T is unaffected either way; the centered overlay is not a popover.

The cascade rule

  • Change the repo, and branch and command both clear. A branch name is meaningless in another repo, and templates can be repo-scoped, so keeping either would leave a stale selection pointing at the wrong thing.
  • Change the branch, and nothing clears. A command is branch-agnostic — cco -n "xyz" means the same thing on any branch.
  • Re-picking the same value is a no-op, not a clear. Clicking the repo chip and choosing the repo already selected must not wipe what you typed.
  • ⌘Z restores the cleared segments as one undo step, so a mis-click costs nothing.
Undo is new scope. The composer has no undo stack today — ⌘Z in the field is AppKit's own text undo and knows nothing about chips. A chip-aware undo that restores a cleared branch and command as a single step has to be built. Small, but it is not free, and it is the one part of slice A that is not pure rendering.
Slice A — implementation detail
  • Rendering: resolved leading tokens become chips; the remainder stays live editable text in the same field. Chips are not text — backspace at position 0 pops the last chip back to text.
  • Delete the trailing projectControl (SessionComposerPalette.swift, the locked and unlocked branches both). The .locked case becomes a chip rendered without a picker affordance.
  • Reuse ProjectDropdownView's list content (:1283) but present it inline, not via .popover at :629.
  • Fixes on the way through: the dropdown's checkmark currently disagrees with the label about which project is selected — one source of truth kills it.
  • Keyboard: left-arrow from field start focuses the previous chip; Return or Down opens its picker; Esc closes the picker without closing the composer.
Slice B — branch as worktree, and why not checkout
  • Never git checkout in the project directory. You run 2–7 parallel sessions against shared trees; a checkout from a launcher would yank the branch out from under another session's uncommitted work. This is the whole reason branch resolves to a worktree.
  • Resolve to an existing worktree first. Enumerate via git worktree list --porcelain; the branch chip lists what already exists before it offers to make anything.
  • Creation is explicit — a + new worktree row, never an implicit side effect of typing a name that does not match.
  • Enumeration needs caching. Shelling out per keystroke is not viable. SessionDraftStore.swift:291-300 already shells to git rev-parse --abbrev-ref HEAD, so the pattern exists — but it is one call at draft time, not a per-keystroke list.
  • Nothing in the composer path knows about worktrees today. Only TaskModel, TaskStore, and OrphanTriageStore mention them.
What slice 1 already settled, so this spec does not re-open it
  • Session naming needs no rule. An unpinned session's sidebar name is the live terminal title, so -n test reaches the name by itself a few seconds after launch. Observed on two runs.
  • The remainder does not blanket-run — it filters that project's templates and appends a Run "…" row. Blanket-running would break ghostties orchestrator.
  • Ad-hoc commands need the login-shell wrapper. exec 'cco' '-n' 'test' verified on disk; cco is a zsh function and dies under /bin/sh -c.
  • Never claim -n as an app flag — it is yours.
