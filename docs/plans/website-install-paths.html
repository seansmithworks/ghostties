Surfacing brew + npx on ghostties.org

Ghostties · web lane · 2026-08-09 · Plan for review

Both terminal installs shipped and are verified live. The site still presents the DMG as the only path. This plan closes that gap across two pages, fixes an un-automated release step found along the way, and corrects one trust claim that is no longer accurate.

Scope is deliberately narrow: no redesign, no new visual world, no touching the hero's ghost choreography.

Status 2026-08-09: paused, nothing built for real. Design is settled through mockups; no repo file has been changed. Working mockups lived in a session scratchpad and are ephemeral — if this is picked up in a new session, they are gone and this document is the record.

Timing at the site's ~0.025s/char rate, uniform 0.35s gaps: line-3 @5.65s · line-4 @7.0s · line-5 @7.825s · line-6 @8.85s, ending ~9.25s. Lines 1–2 and every ghost animation (g0–g7) are untouched.

Build note that cost a round — the .line must stay a block <div> with the button nested inside it. Making the line itself a <button> breaks three things at once: buttons are inline-block so brew and npx flow side by side instead of stacking; text-indent: -2ch (the hanging indent positioning the +) does not apply, so stray + glyphs escape the width: 0 clip and float on the page mid-animation; and the green reveal background paints per-button instead of across the line.

The shipped line-6 already had the right pattern — <span aria-hidden>+ [</span>, then the interactive element, then <span aria-hidden>]</span>. Copy it rather than describing the behaviour and leaving the structure open.

Three constraints that shaped this

1. The brew command cannot go in the hero terminal

brew install --cask seansmithworks/tap/ghostties is 48 characters, 50 with the +  diff prefix. The terminal is width: 46ch on desktop, and below 480px it drops to 16px mono inside calc(100vw - 72px) — roughly 25ch at 320px. It would clip mid-word on every phone.

This is why the hero carries the short path and /download carries the recommended one in full.

2. The typewriter cannot wrap

Every line animates width: 0 → Nch with steps(N) under white-space: nowrap. A line that reflows breaks the mechanism outright. So "two lines" means two real .line divs, not one line that wraps at a breakpoint.

On desktop they stack as two short options under the green block, which reads as intentional rather than as overflow.

3. The copy glyph must sit outside the typed character count

Character budget at 320px is ~25ch. Measured:

Candidate Width Fits 320px (~25ch)?
+ npx ghostties-install 23ch Yes, with margin
+ [npx ghostties-install] 25ch Exactly at budget, zero margin
+ [npx ghostties-install ⧉] 27ch No — clips
+ [download now] 16ch Yes

So the copy button is rendered after the animated span, outside the width animation. Note .line has overflow: hidden, so the button needs a wrapper rather than absolute positioning inside the line.

Bug found in scope — the homepage DMG URL is never bumped

index.html:594 hardcodes .../releases/download/v0.1.0-beta.21/Ghostties.dmg, but scripts/update-web-version.py rewrites that URL in download.html only. Its own comment asserts the opposite: 

# 1. DMG download URL — only download.html has one. (index.html links to /download.)

That comment is wrong, and the HTML at index.html:590 confirms it is a known manual step ("Hardcoded DMG URL — bump the version tag with each release"). It is correct today only because someone remembered.

Fix at the root: add web/index.html to that rule and correct the comment. The alternative — pointing the hero at /download — routes around the bug instead of fixing it, and costs a click.

Neither new command carries a version number. brew install --cask seansmithworks/tap/ghostties and npx ghostties-install both resolve their own versions, so they need no new regexes and cannot be mangled by the bump job. The only version-bearing string added anywhere is the one already handled.

Accessibility

  • Copy controls are real <button>s with an accessible name ("Copy install command"), not styled spans.
  • An aria-live="polite" region announces "Copied" — the visual state change alone is not enough.
  • The hero copy button must toggle visibility, not just opacity, or a keyboard user tabbing during the 10s animation lands on an invisible control.
  • Commands stay selectable text. Copy-to-clipboard is an accelerator, never the only way to get the string.
  • Inherited debt, flagged not fixed: DESIGN.md §7 records that 17 homepage animations already ignore prefers-reduced-motion. This adds two more. Minimum bar here: the copy affordance appears instantly under reduce.

Verification

Two review rounds minimum, non-negotiable on this repo. The website lane has a documented three-for-three record of each round's fixes introducing the next round's defects. One passing round is not evidence.

  1. Dispatch real clicks on both hero CTAs and all three /download actions at 320 / 375 / 768. A rendered element is not a reachable one — that is exactly what PR #95 shipped to fix.
  2. No horizontal page scroll at 320px, and confirm line-6 does not clip.
  3. Screenshot diff at 1280 and 375, before/after, with an ~11s settle. Treat anything under 0.14% as noise (DESIGN.md §2).
  4. Clipboard actually receives the string — read it back, don't trust a "Copied" label.
  5. Dry-run the version script against a fake tag and confirm it rewrites both pages.
  6. Run the impeccable detector over both changed pages once, at the end.

Risks

  • Merging to main is a production deploy (rootDirectory = web). There is no staging step.
  • 481–719px is unaddressed site-wide (DESIGN.md §5) — the new command blocks must not overflow in that band, which the existing audit already flagged as a trouble zone.
  • The hero is the most fragile surface on the site. Editing the typewriter means touching steps() counts, keyframe widths, and char-count comments that must stay in sync with the visible text.

Product section cleanup — IN SCOPE (added 2026-08-09)

Scope expansion, deliberate. These are pre-existing defects shipping on ghostties.org today, not caused by the install-path work. Sean's call to fix them in the same pass rather than file them.

  • Product captions attach to the wrong window. .product-window { margin: 0 auto 56px } puts 56px between a window and its own caption, and 0px between that caption and the next window. So "four sessions, one window" sits flush against the second window and reads as its header. Fix: move the gap — window margin-bottom: 12px, caption margin-bottom: 56px. Check the max-width: 480px block too, which sets its own .product-window { margin-bottom: 28px } and .product-caption { margin-top: 8px } and has the same inversion.
  • The two product videos are framed inconsistently — RESOLVED as "leave it". A CSS crop was built to hide the mismatch, then reverted (dbf0c5306). It was the wrong direction: it deleted the good asset's best feature to disguise the bad asset's flaw.

    Proven by inspecting the sources, not by reading CSS. Both files are 1520×950. product-flow.mp4 contains full window chrome — traffic lights, + button, tab icon, globe. product-sessions.mp4's top ~40px is blank background, then straight into PINNED / Last login:. The chrome was never captured. No CSS can recover pixels that do not exist.

    Standing decision (2026-08-09): the app has changed substantially since these clips were recorded, so every product asset needs re-shooting regardless. Fixing one clip now is wasted work. This PR fixes the container so the new recordings drop into a correct frame.
