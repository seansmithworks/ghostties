Ghostties vNext — the open ground is what your agents shipped

Project: Ghostties 2026-09-29 Draft
Thesis Every cockpit already shows per-session status, and cmux (27.5k stars, same Ghostty + Swift stack) holds the "native agent sidebar" spot, so status alone isn't a position. What nobody does is carry the session past the pull request: this agent pushed this commit, that commit is building on Vercel, prod is now red, and the fix is one click back into the same thread. Ghostties can own that link because it already knows which terminal is which agent (the GHOSTTIES_SESSION_ID hook join). The link is built entirely on public CLI, webhook and hook data, so it needs no vendor's permission. Build the Vercel deploy chip on the session row first. Design its data as an open, multi-provider event format, with Vercel as the first provider. That same piece becomes the Marketplace-role portfolio artifact.

Honest findings

  • cmux is the incumbent, not a peer. It's a Ghostty-based native Swift sidebar with PR status, ports and attention rings, has 27.5k stars, and has an iOS app in TestFlight (repo).
  • Every platform owner shipped a cockpit in 2026. Claude's claude agents, the Codex app, Cursor 3, the Copilot app, Devin Desktop, and iTerm2 3.7's built-in Claude status (agent view, iTerm2).
  • Per-session status and PR checks are table stakes. Claude's agent view colors PR labels by check state, and Superset rows show checks (docs, Superset).
  • Deploy state is pull-only everywhere. Vercel's MCP and CLI only answer when asked, webhooks need a public receiver, and every menu bar app polls (MCP). Meanwhile agents trigger more than 50% of Vercel deploys, per Vercel's own numbers (source).
  • No cross-provider event model exists. Vercel sends webhooks, Netlify signs its webhooks, Cloudflare sends to a queue, Render limits webhooks to Pro, and Fly has none (Cloudflare, Fly).
  • ghostties.org has no analytics. That is the #1 must-have gap for the Growth role, which asks for "measurable outcomes … chose what to measure" (posting).
  • Vercel design leadership may be in flux (unverified). Both named leaders' LinkedIn headlines point to other companies (Hearth, Muñoz Solera).
  • Vercel is hiring for the Ghostties thesis. A "PM, Software Factory" posting (today) says "human time and human attention has become the bottleneck" (posting). A matching design role is likely to follow (inferred).

Avenues, mild → wild

Numbering continues from the 2026-09-05 set. Killed as crowded: a per-PR preview button (Conductor and Superset have it), hook status as a differentiator (cmux, iTerm2), cloud VMs (cmux, Codex, Warp Oz), and diff/kanban review surfaces (every ADE has them, and they break the non-IDE anti-goal).

Mid — a real feature

28. Open deploy-event spec + gt adaptersMIDCost M

  • Why now: extends #11. One JSON shape: provider, project, commit, state, URL, log URL, time. Adapters (gt deploys --provider vercel|railway|netlify|fly) write it locally, and the app, the menu bar and other terminals read it.
  • Evidence: five providers use five different event mechanisms (see Peers below).
  • Threat: Vercel adds push to its MCP (medium). Even then, cross-provider stays open.
  • Vercel tie: Marketplace's partner side ("partners creating and operating integrations").
  • Open-not-exclusive: that's the point. Vercel is the reference adapter, and Railway is second because it sends webhooks on every state change.

29. Agent asks, human grantsMIDCost M

  • Why now: the CLI can install Marketplace integrations as JSON, and Connect went GA with short-lived, task-scoped tokens (Connect). The card shows provider, scope, environment, cost tier and expiry. Approving runs vercel integration add. The grant then sits on the row as a chip that shows its expiry.
  • Evidence: the posting's bonus line is "workflows that move between human approval and autonomous action" (posting).
  • Threat: Anthropic's permission prompt grows service grants (medium).
  • Vercel tie: Marketplace + Connect. This is the strongest single portfolio piece.
  • Open-not-exclusive: the card is generic. Vercel drives it first, and Supabase or Neon direct installs can plug in.

30. One approval queue across parallel sessionsMIDCost M

  • Why now: merges #16. NeedsYouZoneView exists. Turn it into a single queue of every pending permission, grant and prod action across Claude and Codex, answerable without switching terminals. Agent-started promote or rollback always goes through this queue.
  • Evidence: eve and Vercel Agent both require human approval, but only in Slack or the dashboard (eve).
  • Threat: Warp's unified notification center (medium) (Warp).
  • Vercel tie: Marketplace (the approval seam).
  • Open-not-exclusive: hook-based, so it works with any CLI that emits permission events.

32. Session ledger via AI GatewayMIDCost L

34. Push, not poll: a relay on VercelMIDCost M

  • Why now: Vercel webhooks need a public receiver, and a laptop can't be one. A tiny relay hosted on Vercel receives the deployment.* events, checks their signatures, and forwards them to the Mac in real time.
  • Evidence: the webhooks fire .created/.ready/.error with signatures (hookdeck).
  • Threat: Vercel ships native push (low-medium).
  • Vercel tie: Marketplace. It's a candidate Marketplace listing in its own right.
  • Open-not-exclusive: the relay accepts Railway and Netlify webhooks in the #28 format.

Wild — a repositioning

35. Ghostties as the agent-side client of Vercel ConnectWILDCost L

  • Why now: Connect's consent flow is v1 and designed from the dashboard. Ghostties becomes the place where each agent session holds its own credentials: scoped to that session, and expiring automatically when the session closes.
  • Evidence: "Credentials that used to sit in environments long after the work finished now expire on their own" (Connect). The April breach came through a leaked OAuth token (bulletin).
  • Threat: Vercel builds its own local agent (low).
  • Vercel tie: Marketplace + Connect, the "how agent access should work next" line.
  • Open-not-exclusive: Vercel-first. Any short-lived credential broker could plug in later.

36. A bot console for one personWILDCost L

  • Why now: the sidebar lists every agent acting on your behalf: coding sessions, scheduled agents, browser agents. Each shows its scopes, live grants, last action and a revoke button. BotID lets sites verify bots; this is the other side, where the person manages them.
  • Evidence: Vercel verifies bots through signed Web Bot Auth identities (changelog). Nobody offers a console for the individual (inferred).
  • Threat: an OS vendor or a password manager (low within 12 months).
  • Vercel tie: BotID team (none of the three open roles).
  • Open-not-exclusive: Web Bot Auth is an IETF draft, so this is open by construction.
